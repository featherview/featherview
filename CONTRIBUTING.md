# Contributing

Thanks for helping! Featherview is small and opinionated; these are the ground rules.

- **Bugs:** Help › Report a Bug… in the app opens the issue form with your version filled in.
  Attach the file that fails, or say which camera or app wrote it.
- **Ideas and feedback:** [Discussions](https://github.com/featherview/featherview/discussions).
- **Security problems:** see [SECURITY.md](SECURITY.md), please not in public issues.
- **Conduct:** everyone here follows the [Code of Conduct](CODE_OF_CONDUCT.md).

## Code

Read [AGENTS.md](AGENTS.md) first: stack, commands, layout, performance budgets and conventions
(it's written for coding agents, and works for people too). In short:

- Swift 6, Swift Package Manager, full Xcode selected. `swift build`, `swift test`,
  `scripts/bundle.sh debug`.
- Logic goes into `FeatherviewCore`, test first (Swift Testing). Test images are generated by
  `Fixtures`, never committed.
- A slower launch or image swap is a bug: measure with `featherview-bench` before and after.
- Never lose user data: temp file and swap, never overwrite in batch output, delete means Trash.
- User-facing text is translatable; layout uses leading/trailing.
- Conventional commit messages (`feat:`, `fix:`, `test:`, `docs:`, `chore:`).

## Clean room

Featherview is inspired by the *workflow* of a classic Windows viewer and must never derive from
another product's code or assets. Don't contribute code, icons, images, UI text or help text taken
from another viewer, and don't decompile or read its files. Matching single-key shortcuts is fine.
Behaviour you observed as a user, described in your own words, is welcome in an issue.
